# 服装品牌打样开发与版型修订工作台

为服装产品开发团队提供款式档案、样品轮次、尺寸实测、部位批注、替代改版方案、审核锁定和修订历史。

## 技术栈

React + MUI + Redux Toolkit + RTK Query + React Router + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62045`。

## 核心工作流

- 从款式档案进入开发轮次，维护尺码、面辅料、色卡和工艺要求。
- 对比两轮尺寸实测，自动高亮超出容差的部位并关联试穿意见。
- 点击样衣图片部位添加批注，或由版师提交替代方案和责任人。
- 负责人采纳方案、填写未提交草稿，审核完成后锁定轮次并保留完整历史。

## 交样批次（交样回执 / 尺寸实测 / 审核锁定）

「交样批次」页把供应商交样回执、尺寸实测和审核锁定接成同一份批次（MSW 服务端为真相源）：

- **回执幂等**：回执带供应商单号与修订号；同号同修订重传只算一次（台账标 `同号重传·仅记录`）；晚到的旧修订只登记为过期件，不覆盖现行尺寸与判定。
- **并发提交**：批次带版本号，两名跟单员同时提交时先到生效；后到收到 409，现场值保留在本地并逐项列出生效值差异。
- **失效重算**：尺寸实测或批注 / 改版方案一旦变化，尺寸与方案指纹改变，超差判定与锁定结论立即失效并按新依据重算；未重新确认不能锁定，锁定失效后未重新确认不能进入定版。
- **旧草稿升级**：没有供应商单号的旧草稿不并入批次，回填单号后升级为首版（修订 1）。
- **写入失败续传**：供应商系统写入失败时，回执作为「未完成回执」保留（含原始载荷、错误、尝试次数），可一键原载荷重试；成功（含幂等重复）后自动从队列移除。

服务端规则见 `src/api/batchHandlers.ts`，指纹 / 超差纯逻辑见 `src/features/batchLogic.ts`。
